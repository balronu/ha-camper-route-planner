# Camper Route Planner v0.1.0-beta.8

## Deutsch

### Änderungen

- Die Custom-Card-Katalogregistrierung verwendet jetzt den korrekten nackten
  Elementnamen `camper-route-planner-card`.
- `getStubConfig()` liefert ausschließlich `{ entry_id: "" }`; der Präfix
  `custom:` bleibt der tatsächlichen Lovelace-Kartenkonfiguration vorbehalten.
- Der visuelle Editor, die automatische Config-Entry-Erkennung und Vorschauen
  ohne Routinganfrage sind gegen den Kartenkatalogvertrag abgesichert.
- Leaflet-Karten werden vor DOM-Rebuilds und beim Entfernen der Vorschau sauber
  zerstört und beim erneuten Einfügen wieder aufgebaut.
- Die Leaflet-Instanz bleibt von anderen Karten, einschließlich Flightradar24,
  isoliert.

### Installation und Kompatibilität

In HACS das Repository als **Custom repository** hinzufügen und die Pre-release-
Version `v0.1.0-beta.8` auswählen. Alternativ kann
`custom_components/camper_route_planner/` kopiert und Home Assistant danach
neu gestartet werden. Die Version ist für Home Assistant 2026.10.x validiert.
Bestehende YAML-Konfigurationen, Config Entries und Ressourcen anderer Karten
werden nicht verändert. Ein bereits geöffnetes Dashboard kann einen normalen
Browser-Reload benötigen, damit die versionierte Resource geladen wird.

### Validierung und bekannte Einschränkungen

- Python, HA-2026.10.1-Fixtures, Frontend, Chromium Desktop/Mobile, Hassfest,
  Gitleaks und Main-/Tag-CI sind erfolgreich.
- Die automatisierte Testabdeckung ist erfolgreich, aber die tatsächliche
  Darstellung in der produktiven Home-Assistant-Kartenauswahl muss noch
  bestätigt werden.
- Dies ist eine Beta mit deterministischem Mock-Routing und keine geprüfte
  Wohnmobilnavigation. Nakordoni-Live-Aufrufe, VM 104 und Dashboards wurden
  nicht verändert.

## English

### Changes

- Custom-card catalog registration now uses the bare element name
  `camper-route-planner-card`.
- `getStubConfig()` now returns only `{ entry_id: "" }`; the `custom:` prefix is
  reserved for the actual Lovelace card configuration.
- The visual editor, automatic Config Entry discovery, and previews without a
  routing request are covered by the card-picker contract tests.
- Leaflet maps are destroyed before DOM rebuilds and when a preview is removed,
  then rebuilt when it is inserted again.
- The Leaflet instance remains isolated from other cards, including
  Flightradar24.

### Installation and compatibility

In HACS, add the repository as a **Custom repository** and select the
`v0.1.0-beta.8` pre-release. Alternatively copy
`custom_components/camper_route_planner/` and restart Home Assistant. The
version is validated against Home Assistant 2026.10.x. Existing YAML
configuration, Config Entries, and resources belonging to other cards are not
changed. An already open dashboard may need a normal browser reload to load
the versioned resource.

### Validation and known limitations

- Python, HA 2026.10.1 fixtures, frontend, Chromium desktop/mobile, Hassfest,
  Gitleaks, and Main/tag CI passed.
- Automated coverage is successful, but the actual rendering in the
  productive Home Assistant card picker still requires confirmation.
- This is a beta using deterministic mock routing, not verified motorhome
  navigation. No live Nakordoni calls, VM 104 changes, or dashboard changes
  were made.
