# Camper Route Planner v0.1.0-beta.19

## Deutsch

Beta.19 aktiviert den Nakordoni-Motorhome-Laufzeitpfad für einen kontrollierten
manuellen Praxistest in Home Assistant.

### Änderungen und Fehlerbehebungen

- Der ausgewählte Provider wird aus den aktuellen Config-Entry-Optionen
  aufgebaut und nach Optionsänderungen neu geladen.
- Mock, Nakordoni und Nakordoni Motorhome bleiben getrennte Backend-Pfade;
  es gibt keinen stillen Mock-Fallback.
- Der asynchrone Home-Assistant-HTTP-Transport unterstützt Bearer-Key,
  Timeout, begrenzte Quota-Header und das dokumentierte `via`-Format.
- Der explizit ausgewählte Provider `Nakordoni Motorhome` wird mit der
  Home-Assistant-aiohttp-Session und dem gespeicherten Key live aufgerufen;
  Mock-Fallbacks sind ausgeschlossen.
- GeoJSON-Routengeometrie wird korrekt von `lon,lat` nach `lat,lon`
  normalisiert.
- Motorhome-Fahrzeugwerte stammen weiterhin aus dem ausgewählten Profil.

### Installation und Einschränkungen

Beta.19 ist zum Zeitpunkt dieses Dokuments noch nicht veröffentlicht. Es
wurden keine echten Nakordoni-, Geoapify- oder CARTO-Aufrufe durchgeführt.
Der Praxistest muss eine einzelne Route ausdrücklich manuell starten. Es gibt
keine automatischen Requests, Retries oder Mock-Ersatzrouten. Truck-Routing
darf nicht als geprüfte Wohnmobilnavigation dargestellt werden.

Lokal validiert wurden Home-Assistant-Fixtures, Python, Frontend, Chromium,
Compileall, JSON und HACS-Struktur. Hassfest sowie Quality/Secret-Scan bleiben
für die PR-CI ausstehend.

### Kurzer Home-Assistant-Praxistest

1. Beta.19 nur in einer Testinstallation installieren.
2. Im Options Flow `Nakordoni Motorhome` wählen und den eigenen Developer-Key
   eingeben; der Key bleibt in Home Assistant und wird nicht im Browser gezeigt.
3. Ein Fahrzeugprofil vom Typ `motorhome` auswählen oder anlegen und die
   tatsächlichen Maße/Masse prüfen.
4. Genau eine Route ausdrücklich manuell berechnen und HTTP-Status sowie
   Quota-Hinweise beobachten.
5. Bei 401/403/429 abbrechen und keine Wiederholungen auslösen.

Motorhome-Antworten können Beta-Warnungen und providerabhängige Einschränkungen
enthalten; eine erfolgreiche Route ist keine Navigationsgarantie.

## English

Beta.19 enables the Nakordoni Motorhome runtime path for a controlled manual
Home Assistant field test.

### Changes and fixes

- The selected provider is built from the current Config Entry options and is
  reloaded after options changes.
- Mock, Nakordoni, and Nakordoni Motorhome remain separate backend paths; no
  silent Mock fallback is used.
- The asynchronous Home Assistant HTTP transport supports Bearer keys,
  bounded timeouts, safe quota headers, and the documented `via` format.
- The explicitly selected `Nakordoni Motorhome` provider uses Home
  Assistant's aiohttp session and the stored key for live requests; no Mock
  fallback is used.
- GeoJSON route geometry is normalized correctly from `lon,lat` to `lat,lon`.
- Motorhome dimensions and weight continue to come from the selected vehicle
  profile.

### Installation and limitations

Beta.19 has not been published at the time of this document. No real
Nakordoni, Geoapify, or CARTO requests were made. The Motorhome live path
is only invoked by an explicit manual action. There are no automatic requests,
retries, or Mock replacement routes. Truck routing must not be presented as
verified motorhome navigation.

Local validation covers Home Assistant fixtures, Python, frontend, Chromium,
compileall, JSON, and HACS structure. Hassfest and quality/secret scanning
remain pending in PR CI.

### Short Home Assistant field test

1. Install Beta.19 only in a test installation.
2. In Options, select `Nakordoni Motorhome` and enter the own Developer key;
   it remains in Home Assistant and is never exposed to the browser.
3. Select or create a `motorhome` vehicle profile and verify its actual
   dimensions and weight.
4. Trigger exactly one route calculation manually and observe HTTP status and
   quota information.
5. Stop on 401/403/429 and do not repeat the request.

Motorhome responses may include beta warnings and provider-specific limits; a
successful route is not a navigation guarantee.
