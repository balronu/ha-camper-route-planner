# Camper Route Planner v0.1.6-beta.2

## Deutsch

### Fehlerbehebung

- Die bewusst aktivierte One-shot-Entwicklerdiagnose wird jetzt auch bei
  fehlgeschlagenen Routenberechnungen bereitgestellt.
- Das Frontend ruft den sicheren Bericht nach einem Providerfehler über einen
  ausschließlich für Administratoren verfügbaren WebSocket-Befehl ab.
- Der Bericht kann auch ohne neues Routenergebnis angezeigt und kopiert werden.
- Jeder Bericht wird beim einmaligen Abruf aus dem Backend entfernt; alte
  Berichte werden bei einem neuen Berechnungsversuch verworfen.
- HTTP-Status, Antworttyp, Dauer, API-Version, Zwischenzielanzahl, Fehlercode
  und sichere Restriktionscodes bleiben verfügbar. Ungefilterte Antworten,
  API-Schlüssel und standortbezogene Restriktionsbeschreibungen werden nicht
  gespeichert.
- Die Sicherheitsprüfung für `legal=false` und `restriction_hits` bleibt
  unverändert: eine nicht bestätigte Route wird nicht als erfolgreich markiert.

### Kompatibilität und Tests

Die Beta ist für gezielte Tests vorgesehen. Erfolgsantworten, Restriktionen,
leere/ungültige/HTML-Antworten, HTTP-Fehler, Timeouts, Netzwerkfehler,
Administratorgrenzen, Einmalabruf, Parallelität und mobile Fehlerdarstellung
wurden mit isolierten Fixtures und Browser-Tests geprüft. v0.1.5 bleibt Stable.

VM 104, Zoe, gespeicherte Routen und produktive API-Zugänge wurden nicht
verändert; für die Veröffentlichung wurden keine produktiven NaKordoni-Anfragen
ausgeführt.

## English

### Fix

- The explicitly armed one-shot developer diagnostic is now also provided after
  failed route calculations.
- The frontend retrieves the safe report after a provider error through a
  WebSocket command restricted to administrators.
- The report can be displayed and copied even when no new route result exists.
- Each report is removed from the backend after its one-time retrieval; old
  reports are discarded when a new calculation starts.
- HTTP status, response type, duration, API version, waypoint count, error code,
  and safe restriction codes remain available. Unfiltered responses, API keys,
  and location-bearing restriction descriptions are not stored.
- The `legal=false` and `restriction_hits` safety check is unchanged: an
  unconfirmed route is never presented as successful.

### Compatibility and tests

This beta is intended for targeted testing. Successful responses, restrictions,
empty/invalid/HTML responses, HTTP errors, timeouts, network errors,
administrator boundaries, one-time retrieval, concurrency, and mobile error
display were checked with isolated fixtures and browser tests. v0.1.5 remains
Stable.

VM 104, Zoe, saved routes, and productive API credentials were not changed; no
productive NaKordoni requests were made for this publication.
