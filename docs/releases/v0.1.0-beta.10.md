# Camper Route Planner v0.1.0-beta.10

## Deutsch

Beta.10 bündelt die Frontend-Korrekturen aus Phase 3E und die Options-Flow-
Verbesserungen aus Phase 3F.

### Änderungen und Fehlerbehebungen

- CARTO-Karte bleibt auch ohne berechnete Route geografisch sichtbar.
- Adress- und Zieleingabe bleibt auf Desktop und iPhone stabil.
- Fokus und Cursorposition werden bei Eingaben erhalten.
- Das Layout reagiert auf die tatsächliche Kartencontainerbreite.
- Leaflet-Lifecycle und Flightradar24-Isolation sind abgesichert.
- Koordinaten werden mit höchstens sechs Nachkommastellen angezeigt.
- Vorhandene Fahrzeugprofile können im Options-Flow ausgewählt und bearbeitet
  werden; Werte werden vorausgefüllt und stabile Fahrzeug-IDs bleiben erhalten.
- Fahrzeugtyp, Abmessungen, Gewicht, Kraftstoffart und GPS-Tracker können
  geändert werden. Zoe berücksichtigt weiterhin
  `device_tracker.wohnmobil_zoe`.
- Der gemeinsame Geoapify-Key kann gespeichert, ersetzt oder ausdrücklich
  entfernt werden. Ein leeres Feld löscht einen vorhandenen Key nicht.
- Gespeicherte Optionen werden beim erneuten Öffnen aus Daten und Optionen
  korrekt zusammengeführt; bestehende Beta.9-Konfigurationen bleiben erhalten.

### Installation und Einschränkungen

Beta.10 ist als GitHub-Pre-release für HACS vorgesehen. Die Pre-release muss
in HACS ausdrücklich ausgewählt bzw. aktiviert werden. Die Release-Prüfung
verwendet isolierte HA-2026.10.1-Fixtures, Mock-Daten und Chromium. Ein echter
HACS-UI-Installations-/Update-/Deinstallationslauf, WebKit/iOS und die
Darstellung in einer produktiven Home-Assistant-Instanz wurden nicht geprüft.

Produktive CARTO-, Geoapify- und Nakordoni-Aufrufe wurden nicht durchgeführt.
Das Projekt verwendet weiterhin deterministisches Mock-Routing; es ist keine
geprüfte Wohnmobilnavigation. VM 104, produktive Dashboards, Config Entries,
API-Schlüssel und andere Integrationen wurden nicht verändert.

## English

Beta.10 bundles the Phase 3E frontend fixes and the Phase 3F Options Flow
improvements.

### Changes and fixes

- the CARTO map remains geographically visible before a route is calculated;
- address and destination input remains stable on desktop and iPhone;
- input focus and cursor position are preserved;
- the layout responds to the actual map-container width;
- Leaflet lifecycle and Flightradar24 isolation are hardened;
- coordinates are displayed with at most six decimal places;
- existing vehicle profiles can be selected and edited in the Options Flow,
  with values prefilled and stable vehicle IDs preserved;
- vehicle type, dimensions, weight, fuel type, and GPS tracker can be edited;
  Zoe continues to account for `device_tracker.wohnmobil_zoe`;
- the shared Geoapify key can be stored, replaced, or explicitly removed; an
  empty field does not erase an existing key;
- saved options are merged correctly from data and options when reopened, and
  existing Beta.9 configurations are preserved.

### Installation and limitations

Beta.10 is published as a GitHub pre-release intended for HACS. Explicitly
enable/select pre-releases in HACS. Release validation uses isolated
HA-2026.10.1 fixtures, mocked data, and Chromium. A real HACS UI
install/update/uninstall run, WebKit/iOS, and rendering in a productive Home
Assistant instance were not validated.

No productive CARTO, Geoapify, or Nakordoni requests were made. The project
still uses deterministic mock routing and is not verified motorhome
navigation. VM 104, productive dashboards, Config Entries, API keys, and
other integrations were not changed.
