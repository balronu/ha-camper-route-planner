# Camper Route Planner v0.1.6-beta.1

## Deutsch

### Zweck

Diese Vorabversion verbessert die Fehlerdiagnose für NaKordoni-v3-Routen. Die
aktuelle Stable-Version bleibt **v0.1.5**; diese Beta ist ausschließlich für
gezielte Tests vorgesehen und ersetzt keine Stable-Freigabe.

### Änderungen

- Leere Antworten, ungültiges JSON, HTML-Antworten und HTTP-Fehler werden vor
  bzw. unabhängig vom JSON-Parsing unterschieden.
- Statuscodes 400, 401, 403, 404, 408, 429 und 5xx werden mit stabilen internen
  Fehlercodes und verständlichen Meldungen behandelt.
- Begrenzte bestehende Wiederholungen und `Retry-After`-Informationen bleiben
  erhalten; 429 wird nicht automatisch wiederholt.
- Nicht bestätigte Fahrzeugbeschränkungen verhindern weiterhin eine erfolgreiche
  Routendarstellung. Sichere Restriktionscodes und vorhandene, nicht
  standortbezogene Anbieterhinweise können in der geschützten Diagnose stehen.
- Die optionale administrative Einmal-Diagnose enthält nun Status, Antworttyp,
  Antwortlänge, Dauer, API-Version, Zwischenzielanzahl und Fehlercode, ohne
  API-Schlüssel oder ungefilterte Anbieterantworten zu speichern.
- Die Lovelace-Karte zeigt verständliche deutsche bzw. englische Meldungen und
  kennzeichnet ein vorhandenes Ergebnis nach einem fehlgeschlagenen Versuch
  weiterhin als veraltet.

### Tests und Grenzen

- Die Beta wurde mit isolierten Fixtures, gemockten Antworten und einer
  erfolgreichen v3-Regressionsroute geprüft. Es wurden keine produktiven
  NaKordoni-Anfragen für die Veröffentlichung ausgeführt.
- VM 104, gespeicherte Routen und das Fahrzeugprofil Zoe bleiben unverändert.
- Bei ungewöhnlichen Anbieterantworten kann die Diagnose absichtlich nur
  begrenzte Metadaten enthalten. Eine unzulässige Route wird nicht automatisch
  freigegeben.

### Installation und Rollback

Die Beta kann über die GitHub-Vorabversion oder das Release-ZIP in einer
Testumgebung installiert werden. Vor dem Wechsel ein Home-Assistant-Backup
erstellen. Für produktive Nutzung v0.1.5 Stable verwenden. Ein Rollback auf
v0.1.5 ist ohne Datenmigration vorgesehen; bestehende Profile und gespeicherte
Routen werden nicht absichtlich verändert.

## English

### Purpose

This preview release improves diagnostics for NaKordoni v3 routes. The current
Stable version remains **v0.1.5**; this beta is intended for targeted testing
only and is not a Stable replacement.

### Changes

- Empty responses, invalid JSON, HTML responses, and HTTP errors are classified
  before or independently of JSON parsing.
- Status codes 400, 401, 403, 404, 408, 429, and 5xx responses use stable
  internal error codes and understandable messages.
- Existing bounded retries and `Retry-After` information are preserved; 429 is
  not retried automatically.
- Unconfirmed vehicle restrictions still prevent a route from being presented
  as successful. Safe restriction codes and existing non-location provider
  hints may appear in protected diagnostics.
- The optional administrative one-shot diagnostic now includes status, response
  type, response length, duration, API version, waypoint count, and error code
  without storing API keys or unfiltered provider responses.
- The Lovelace card shows understandable German or English messages and still
  marks an existing result as outdated after a failed recalculation.

### Tests and limitations

- The beta was checked with isolated fixtures, mocked responses, and a
  successful v3 regression route. No productive NaKordoni requests were made
  for this publication.
- VM 104, saved routes, and the Zoe vehicle profile remain unchanged.
- Unusual provider responses may intentionally produce only limited diagnostic
  metadata. An unconfirmed route is never automatically approved.

### Installation and rollback

Install the beta through the GitHub pre-release or its release ZIP in a test
environment. Create a Home Assistant backup before switching versions. Use
v0.1.5 Stable for production. Rollback to v0.1.5 requires no data migration;
existing profiles and saved routes are not intentionally changed.
