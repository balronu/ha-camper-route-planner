# Camper Route Planner v0.1.0-beta.7

## Deutsch

### Fehlerbehebung

- Die Lovelace-Karte wird nicht mehr über `add_extra_js_url()` geladen.
- Das Bundle wird als versionierte `type: module`-Resource im Lovelace-
  Storage-Modus registriert. Dadurch erfolgt die Custom-Element-Registrierung
  erst in der aktiven Lovelace-Registry und der Fehler `Custom element not
  found` nach Reload oder Neustart wird vermieden.
- Die Registrierung ist idempotent: alte Versionen der eigenen Resource werden
  aktualisiert, fremde Ressourcen bleiben erhalten und mehrere Config Entries
  erzeugen keinen Duplikat-Eintrag.
- Beim Entfernen oder erneuten Laden der Integration bleibt die persistente
  eigene Lovelace-Resource erhalten; verwaiste Einträge werden nicht
  automatisch gelöscht. Bei `resource_mode: yaml` bleibt die Resource-Liste
  vollständig benutzerverwaltet und die versionierte URL muss manuell als
  `type: module` eingetragen werden.

### Installation und Migration

In HACS als **Custom repository** die Pre-release-Version `v0.1.0-beta.7`
auswählen. Alternativ kann der Ordner
`custom_components/camper_route_planner/` kopiert und Home Assistant danach
neu gestartet werden. Bestehende YAML-Konfigurationen, Config Entries und
Lovelace-Ressourcen anderer Karten bleiben unverändert. Nach dem Update kann
ein bereits geöffneter Browser einen normalen Reload benötigen, damit das
versionierte Bundle geladen wird.

### Validierung und Einschränkungen

- Python-, HA-2026.10.1-Fixture-, Frontend- und Chromium-Desktop/Mobile-Tests
  decken Setup, Reload, Neustart-Fixture, alte Version, mehrere Entries,
  Browser-Element-Registrierung, Editor-Katalog und den fehlenden Ladekreis ab.
- Hassfest, Gitleaks und die GitHub-Action laufen als verbindliche CI-Gates auf
  dem Release-Commit; ein produktiver HA- oder HACS-UI-Test ist nicht enthalten.
- Dies ist eine Beta mit deterministischem Mock-Routing und keine geprüfte
  Wohnmobilnavigation. Nakordoni-Live-Aufrufe, VM 104 und Dashboards wurden
  nicht verändert.

## English

### Fix

- The Lovelace card is no longer loaded through `add_extra_js_url()`.
- The bundle is registered as a versioned `type: module` resource in Lovelace
  storage mode. This lets Lovelace load it in the active custom-element
  registry and avoids the `Custom element not found` failure after reloads or
  restarts.
- Registration is idempotent: an old version of this integration's resource
  is updated, unrelated resources are preserved, and multiple Config Entries
  do not create duplicates.
- Unloading or reloading the integration leaves the persistent resource in
  place; orphaned entries are not deleted automatically. In `resource_mode:
  yaml`, the resource list remains user-managed and the versioned URL must be
  added manually as a `type: module` resource.

### Installation and migration

In HACS, add the repository as a **Custom repository** and select the
`v0.1.0-beta.7` pre-release. Alternatively copy
`custom_components/camper_route_planner/` and restart Home Assistant. Existing
YAML configuration, Config Entries, and unrelated Lovelace resources remain
unchanged. An already open browser may need a normal reload to load the
versioned bundle after the update.

### Validation and limitations

- Python, HA 2026.10.1 fixture, frontend, and Chromium desktop/mobile tests
  cover setup, reload, restart fixture, old versions, multiple entries,
  browser custom-element registration, the card catalog/editor, and the
  absence of a permanent loading spinner.
- Hassfest, Gitleaks, and GitHub Actions are mandatory CI gates on the release
  commit; no productive HA or HACS UI installation test is included.
- This is a beta using deterministic mock routing, not verified motorhome
  navigation. No live Nakordoni calls, VM 104 changes, or dashboard changes
  were made.
