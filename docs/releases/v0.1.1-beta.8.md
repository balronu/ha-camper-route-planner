# Camper Route Planner v0.1.1-beta.8

## Deutsch

### Änderungen

- Das optionale Feld für den Durchschnittsverbrauch verwendet im nativen Home-Assistant-OptionsFlow direkt einen `NumberSelector`. Es bleibt sichtbar, editierbar und ohne künstlichen Leer-Default; fehlende Eingaben werden als `None` gespeichert. Gespeicherte Dezimalwerte werden beim erneuten Öffnen wieder angezeigt.
- Die Fahrzeugverwaltung verwendet eine einzige dynamische Auswahl: keine Änderungen, vorhandene Profile direkt bearbeiten, neues Fahrzeug hinzufügen oder Fahrzeug löschen. Der frühere Bearbeiten-Zwischendialog entfällt.
- Das Fahrzeugformular ist in Grunddaten, Fahrzeugtechnik sowie Verbrauch und Standort geordnet. Fahrzeugart und Kraftstoffart verwenden native Select-Selectoren.
- Die Lösch-Checkbox wurde aus dem Bearbeitungsformular entfernt. Löschen erfolgt über eine separate Profilwahl und ausdrückliche Bestätigung; Routenreferenzen werden vor dem Löschen angezeigt und nicht stillschweigend entfernt.
- Bestehende Profil-IDs, Zoe-Daten, Maße, Gewicht, Achsen, Emissionsdaten, Erstzulassung, Verbrauch, Tracker und Routenreferenzen werden ohne Migration erhalten.

### Kompatibilität und Grenzen

- Stable `v0.1.0` bleibt unverändert und die Rückfallbasis. Diese Version ist eine Beta-Pre-release.
- Native Home-Assistant-Formulare bleiben vertikal; frei gestaltete Spaltenlayouts sind nicht Bestandteil des OptionsFlow.
- Dezimalkommas werden nur dort normalisiert, wo Home Assistant den Wert als Formularwert an den Flow übergibt. Das tatsächliche Verhalten hängt vom nativen NumberSelector und der Companion-Oberfläche ab.
- Kein Nakordoni-Liveaufruf, keine Installation in VM 104 und keine Änderung produktiver Home-Assistant-Daten.

## English

### Changes

- The optional average-consumption field now uses a direct native Home Assistant `NumberSelector` in the Options Flow. It remains visible and editable without an artificial blank default; missing input is stored as `None`. Existing decimal values are shown again when the form is reopened.
- Vehicle management now uses one dynamic selection: no changes, direct editing of existing profiles, add a vehicle, or delete a vehicle. The former edit intermediary is removed.
- The vehicle form is ordered as base data, vehicle technology, then consumption and location. Vehicle type and fuel type use native Select selectors.
- The delete checkbox is removed from the edit form. Deletion uses a separate profile selection and explicit confirmation; route references are shown and are never removed implicitly.
- Existing profile IDs, Zoe data, dimensions, weight, axles, emissions, registration date, consumption, tracker, and route references are preserved without migration.

### Compatibility and limitations

- Stable `v0.1.0` remains unchanged and is the rollback baseline. This release is a beta pre-release.
- Native Home Assistant forms remain vertical; custom multi-column Options Flow layouts are not included.
- Decimal commas are normalized only when Home Assistant passes the value to the flow. Actual behavior depends on the native NumberSelector and Companion UI.
- No Nakordoni live request, VM 104 installation, or productive Home Assistant data change is performed.
